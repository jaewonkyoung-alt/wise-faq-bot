## Slide 3 — 프로젝트 개요 — 문제 정의

학생에게 필요한 캠퍼스 정보는 이미 공개되어 있으나,  
문제는 정보가 없는 것이 아니라 **찾기 어렵고 오래되어 있다**는 것.

| # | 문제 | 설명 |
|---|------|------|
| ① | 정보가 흩어져 있다 | 동아리·식당·졸업요건 등이 서로 다른 사이트·PDF에 분산 |
| ② | 키워드 검색으로는 답이 나오지 않는다 | 학번·학과·전공유형이 결합된 질의 |
| ③ | 만들어도 유지되지 않는다 | 제작 학생 졸업 후 데이터 갱신이 끊김 → 틀린 정보를 확신 있게 답변 |

**핵심 문제:**  
"챗봇을 만들 수 있는가"가 아니라  
**"개발자가 떠난 뒤에도 데이터가 유지되는 구조를 만들 수 있는가"**

## Slide 4 — 프로젝트 개요 — 최종 목표 · 검증지표

### 최종 목표

출처가 명시된 정확한 캠퍼스 정보 제공 + 비개발자가 웹 관리자 화면에서 데이터를 수정하면 **별도 배포 없이 즉시 답변에 반영**.

### 검증지표 (측정방법 포함)

| 번호 | 목표 | 검증지표 | 측정방법 |
|------|------|----------|----------|
| 1 | 동아리 도메인 질의응답 | 정답률 90% 이상 | 자체 테스트셋 정답 일치율 |
| 2 | 코드 수정 없이 신규 도메인 추가 | 개발작업 최소화·1시간 이내 | 스키마 등록~질의 가능 실측 / **(권한·초기 인덱싱 예외)** |
| 3 | 비개발자 운영 가능 관리도구 | 수정 후 60초 이내 반영 | 저장→동일 질의 재시도 시간 |
| 4 | 환각 억제 | KB 없는 질문 오답률 5% 이하 | 미포함 질문 세트 오답 생성 비율 |
| 5 | 정형 질의 정확도 | 수치형 질의 95% 이상 | 학점·가격·요일 정답 일치 |
| 6 | 실용적 응답속도 | 평균 5초 이내 | p50/p95 응답시간 |

상세 표: [docs/verification.md](../verification.md)

## Slide 5 — 핵심기능

1. **자연어 질의응답** — 하이브리드 검색: 정형=DB, 비정형=임베딩, LLM Tool Calling
2. **출처 표기 및 오답 방지** — 출처 URL·최종수정일, 임계값 미만 시 "확인되지 않음"
3. **비개발자용 관리자 대시보드** — 도메인별 권한, 변경 이력
4. **수정 즉시 반영** — 증분 재색인, 60초 이내, 재배포 불필요
5. **도메인 점진 확장 (스키마 JSON 등록)**  
   ※ **"코드 0줄" 예외:** 스키마 등록·도메인 권한·초기 인덱싱
6. **데이터 신선도 관리** — verified_at, 미검증 시 경고
7. **미응답 질문 수집** — 운영 피드백

## Slide 8 — 핵심기술 스택 및 개발환경

### 1단계 (9~10월) — 상용 API 기반

- RAG 파이프라인(검색 정확도·확장 구조) 검증에 집중
- 상용 LLM API + 하이브리드 검색(DB + Vector Store)

### 2단계 (10~11월) — 로컬 sLLM 교체·비교

- 동일 파이프라인에 로컬 sLLM(EXAONE/Qwen 계열, Ollama) 교체
- 정답률 · 응답속도 · 비용 정량 비교

### ※ 도입 의사결정 포인트 (개인정보·비용 리스크)

**1단계 상용 API는 개인정보(질의 외부 전송)·비용 리스크가 있으므로, 2단계 로컬 비교가 도입 의사결정에 필요.**

## Slide 9 — 전체 아키텍처 — 하이브리드 검색

하이브리드 검색을 채택하는 이유:

| 유형 | 예 | 처리 |
|------|-----|------|
| **정형 데이터** | 학점 · 가격 · 운영시간 | DB 조건 조회 — 값의 정확성이 필수 ("학식 A세트 가격은?", "동아리 모집 마감일?") |
| **비정형 데이터** | 동아리 소개 · 공지 | 임베딩 유사도 검색 — 의미 기반 ("밴드 동아리 추천해줘", "프로그래밍 관련 동아리?") |

LLM Tool Calling으로 질의 유형에 따라 DB 조회 / 벡터 검색을 선택·조합하여 응답 생성.  
출처(URL · 최종수정일)를 함께 제시하고, 신뢰도 임계값 미만이면 **"확인되지 않음"**으로 답변.

## Slide 10 — 시스템 구성도

```
클라이언트 (카카오톡 / 웹)
        ↓
API · 오케스트레이터 (LLM Tool Calling)
        ↓
   ┌────┴────┐
  DB      Vector Store
정형 데이터  비정형 임베딩
        ↕
Admin Dashboard (비개발자 관리)
```

| 구분 | 내용 |
|------|------|
| **[현재]** | 동아리 KB · 관리자 · 상용 LLM |
| **[이후]** | 추가 도메인 · 로컬 sLLM |
