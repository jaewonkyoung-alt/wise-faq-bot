# 상세 설계 — 모듈(계층) 구조

## 계층

| 계층 | 구성 파일 | 책임 |
|------|-----------|------|
| 표현 | `routes/*.ts`, `kakao/responseBuilder.ts`, `public/admin/*` | HTTP 입출력, 카톡 Skill JSON 변환 |
| 응용(서비스) | `services/kakaoDialog`, `askService`, `graduationService`, `kbGraduation`, `roomCode`, `clubStore`, `reindex`, `unanswered`, `kakaoSession` | 업무 규칙, 대화 흐름, 하이브리드 경로 결정 |
| 인프라 | `db/database.ts`, `embeddings/embedder·similarity`, `llm/provider.ts` | DB 연결·마이그레이션, 외부 API 어댑터 |
| 데이터 | SQLite(`data/wise.db`), 폴더 KB(`data/kb`), 시드(`data/seed`) | 영속 데이터 |

- 의존 방향은 위 → 아래 단방향이다.
- `middleware/adminAuth`, `types/*` 는 계층 공통이다.

## 설계 원칙

- 라우터는 서비스만 호출한다.
- 사실(데이터)은 SQL·폴더 KB에서만 가져오고, LLM은 문장만 생성한다.
- 인증은 라우트 단위로 명시한다(전역 미들웨어 금지).

## 확장 규칙 (NFR-05)

새 도메인 추가 시 파일 3개를 추가하고, 기존 코드는 메뉴 분기 1곳만 수정한다.

1. `services/<domain>Service.ts`
2. `routes/<domain>.ts`
3. `db/database.ts` 에 테이블 추가
4. (+) `services/kakaoDialog.ts` 메뉴 분기 1곳
