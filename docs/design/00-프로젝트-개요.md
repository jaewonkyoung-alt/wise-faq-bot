# 프로젝트 개요

## 배경 · 문제정의

| # | 문제 | 내용 |
|---|------|------|
| 1 | 정보 분산 | 졸업요건·동아리·강의실 정보가 홈페이지·학과 PDF·카톡방에 흩어져 있음 |
| 2 | 탐색 비용 | 학생이 연도·단과대·학과별 PDF를 직접 찾아야 함 (메뉴 깊이) |
| 3 | 갱신 장벽 | 비개발 직원·학생회가 챗봇 데이터를 직접 고치기 어려움 |
| 4 | 신뢰성 | 일반 LLM은 캠퍼스 데이터가 없어 환각·출처 불명 답변 |

## 개발 목표

- **G1 카톡 1순위 채널** — 설치 없이 이미 쓰는 카카오톡에서 메뉴·자연어로 질의
- **G2 하이브리드 응답** — 정형 조회(졸업요건·지도) + 비정형 RAG(동아리), 근거 없으면 거절
- **G3 비개발자 운영** — 관리자 웹·폴더 KB로 재배포 없이 즉시 반영
- **G4 점진적 확장** — 도메인(공지 → 알림톡 등)을 모듈 단위로 추가 가능한 구조

## 범위

| 구분 | 포함 범위 (1차 · 2026-11-15) |
|------|------|
| 학생 채널 | 카카오톡 챗봇: 메뉴, 졸업요건 조회, 호실 위치, 동아리 질의, 공지 조회 |
| 관리자 | 웹 대시보드: 토큰 로그인, 졸업요건·동아리·공지 CRUD, KB 재스캔, 미답변 관리 |
| 데이터 | SQLite DB + 폴더 KB(data/kb: 졸업요건 PDF·info.md, 지도 JSON) |
| 품질 | 출처 표시 · 미존재 거절 · 미답변 로그 수집 |

| 구분 | 제외 범위 (후순위) |
|------|------|
| 알림톡 | 카카오 알림톡 일괄 푸시 (비즈니스 채널 심사 필요) |
| sLLM | 온디바이스/로컬 소형 LLM 교체 |
| 회원 | 학생 로그인·개인화 (카톡 사용자 키만 세션에 사용) |

## 사용자

- **학생** — 재학생·신입생
- **관리자** — 교직원·학생회

## 기대효과

- 탐색 단계 단축: PDF 검색 → 카톡 버튼 3번 선택
- 24시간 응대: 수동 상담 공백 없이 자동 응답
- 운영 비용 절감: 코드 수정 없이 관리자가 갱신
- 신뢰도 확보: 출처·갱신일 제시, 모르면 거절

## 기존 대안 비교

| 대안 | 즉시 조회 | 출처·정확성 | 비개발자 갱신 | 추가 설치 없음 | 한계 → 본 프로젝트 차별점 |
|------|:---:|:---:|:---:|:---:|------|
| WISE 홈페이지 · 학과 PDF | ✕ | ○ | △ | ○ | 메뉴 깊이·연도별 PDF 탐색 → 카톡 슬롯(연도→단과대→학과) |
| 일반 ChatGPT · 웹 LLM | ○ | ✕ | ✕ | ○ | 캠퍼스 DB 없음·환각 → 정형 DB 조회 + 근거 없으면 거절 |
| 카카오 채널 상담원 수동 응대 | △ | ○ | ○ | ○ | 야간 공백·인건비 → 스킬 서버 자동 응답 |
| 상용 챗봇 SaaS | ○ | △ | △ | ○ | 학교 폴더 KB·로컬 DB 커스텀 약함 → 폴더 KB + 관리자 CRUD |
| 전용 모바일 앱 | ○ | ○ | △ | ✕ | 설치·배포 장벽 → 카카오톡 1순위 채널 |
| **본 프로젝트** | ○ | ○ | ○ | ○ | 하이브리드(정형+RAG) · 비개발자 운영 · 점진 확장 |

비교 기준은 문제정의 4항목(분산·탐색·갱신·신뢰)에서 도출했다.
