# 개발 방법론 — 점증형(Incremental) 모델

## 모델 비교와 선정

| 모델 | 특징 · 본 프로젝트 적합성 | 판단 |
|------|------|:---:|
| 폭포수 | 단계 순차 · 요구 변경에 취약 → 도메인이 계속 추가되는 구조와 맞지 않음 | ✕ |
| 프로토타입 | 화면 시안 검증에 강함 → 핵심 위험은 UI가 아니라 데이터·응답 정확성 | △ |
| 스크럼 | 팀 스프린트·역할 분담 전제 → 1인 개발, 의식(ceremony) 비용 과다 | △ |
| **점증형** | 핵심 기능부터 증분 단위로 완성·인도 → 컨셉 '점진적 확장'과 일치, 매주 발표로 검증 | **채택** |

## 용어

- **점증형 모델**: 시스템을 기능 묶음 단위로 나누어 차례로 완성·인도하는 개발 방식
- **증분(Increment)**: 한 번에 인도되는 기능 묶음. 각 증분은 분석 → 설계 → 구현 → 테스트를 1회전 수행한다

## 증분 계획

| 증분 | 범위 | 시기 | 상태 |
|------|------|------|------|
| 증분 1 | 졸업요건 조회 + 관리자 웹 | 1~2주 | 인도 완료 |
| 증분 2 | 지도(호실) · 동아리 RAG | 1~2주 | 인도 완료 |
| 증분 3 | 공지 CRUD · 카톡 E2E | 3~5주 | 진행 |
| 증분 4 | 보안 · 운영 · 품질 | 6~7주 | 예정 |
| 확장 | 알림톡 · sLLM | 이후 | 후순위 |
