## UC-02 졸업요건 조회

| 항목 | 내용 |
|------|------|
| 액터 | 학생 (주) · 관련 요구사항 FR-02, FR-03, NFR-01, NFR-07 |
| 개요 | 학생이 입학연도·단과대학·학과를 선택해 해당 졸업요건과 원문 PDF 링크를 받는다 |
| 사전조건 | 카카오톡 채널 추가 · 해당 연도/학과 데이터가 폴더 KB 또는 DB에 등록되어 있음 |
| 사후조건 | 졸업요건 답변 반환 · 대화 상태를 메뉴로 초기화(실패 시 UC-13 미답변 기록) |
| 기본 흐름 | 1) '졸업요건' 버튼 선택 2) 시스템이 입학연도 버튼 제시 3) 연도 선택 4) 단과대학 버튼 제시·선택 5) 소속 학과 버튼 제시·선택 6) 폴더 KB → DB 순으로 조회 7) 학점·요건 요약 + PDF 링크 버튼 응답 |
| 대안 흐름 | A1) '22학번 컴공 졸업요건'처럼 한 문장 입력 → 연도·학과 동시 인식 후 6)으로 이동 A2) 학과가 8개 초과 → '더보기' 버튼으로 페이지 이동 |
| 예외 흐름 | E1) 연도 해석 실패 → 예시와 함께 재입력 요청 E2) 학과 후보 여러 개 → 후보 버튼 재제시 E3) 데이터 없음 → '확인되지 않음' 안내 + 미답변 기록 E4) 공개 URL 미설정 → 링크 없이 안내문 |

## UC-04 동아리 질의

| 항목 | 내용 |
|------|------|
| 액터 | 학생 (주), LLM API (보조) · 관련 요구사항 FR-05, NFR-01, NFR-02 |
| 개요 | 학생의 자유 문장 질문을 정형 조회 또는 의미 검색으로 처리해 출처가 포함된 답변을 받는다 |
| 사전조건 | 동아리 데이터 등록 · 임베딩 색인 완료(UC-10) |
| 사후조건 | 답변 + 출처(URL·갱신일) 반환, 또는 거절 + 미답변 기록 |
| 기본 흐름 | 1) '동아리' 선택 후 질문 입력 2) LLM이 경로 결정(정형 조회 / 의미 검색 / 거절) 3) 정형: 이름·분과로 DB 조회 / 의미: 질문 임베딩 ↔ 청크 코사인 유사도 상위 3개 4) 조회된 사실만으로 답변 문장 생성 5) 출처 목록을 붙여 응답 |
| 대안 흐름 | A1) '와이즈코딩 연락처'처럼 이름이 명확 → 정형 조회만 수행 A2) LLM 미설정(mock) → 규칙 기반 경로 결정·템플릿 답변 |
| 예외 흐름 | E1) 동아리와 무관한 질문 → 거절 안내 + 미답변 기록 E2) 최고 유사도 < 0.35 → '확인되지 않음' E3) LLM 호출 실패·지연 → 오류 안내 메시지 반환(카톡 5초 제한 준수) |

## UC-09 공지 관리 (구현 예정)

| 항목 | 내용 |
|------|------|
| 액터 | 관리자 (주) · 관련 요구사항 FR-10, NFR-03, NFR-04 |
| 개요 | 관리자가 공지를 등록·수정·삭제하면 카카오톡 공지 조회(UC-05)에 즉시 반영된다 |
| 사전조건 | UC-06 관리자 로그인 완료(유효한 관리자 토큰) |
| 사후조건 | notices 테이블 갱신 · 게시 중이고 게시 기간 내인 공지만 학생에게 노출 |
| 기본 흐름 | 1) 관리자 웹 '공지' 메뉴 선택 2) 목록 조회 3) '새 공지' 선택 4) 제목·본문·링크·고정 여부·게시 기간 입력 5) 저장 → 입력값 검증 6) DB 저장 후 목록 갱신 7) 학생이 카톡 '공지' 선택 시 최신순(고정 우선) 표시 |
| 대안 흐름 | A1) 기존 공지 선택 → 수정 후 저장 A2) '게시 안 함' 저장 → 초안으로 보관(학생 비노출) |
| 예외 흐름 | E1) 토큰 불일치 → 401, 로그인 화면 복귀 E2) 제목·본문 누락 → 400 + 입력 안내 E3) 링크가 http(s)가 아님 → 저장 거부 E4) 삭제 대상 없음 → 404 |
