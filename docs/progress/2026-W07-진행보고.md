## 2. 졸업요건 — 공식 기준 -&gt; 관리자 화면에서 확인

- 1.  학교 가이드에서 정리한 42개 학과 공식 기준을 관리자 화면에 표시
- 2.  단과대학 선택 · 학과 검색으로 찾고, 학과별 학번 · 학생구분 기준을 한눈에 확인
- 3.  학번 · 학생구분을 고르면 카톡에 나갈 답변을 미리 보기
- 4.  손으로 넣던 졸업요건 입력 칸은 '보충 등록'으로 접어 둠

<sub>(화면 캡처 2장)</sub>

## 3. 공식 PDF 올리기 — 학교 PDF -&gt; 바뀐 칸만 미리보기

- 1.  관리자는 학교 홈페이지의 학과별 졸업기준 PDF를 끌어다 놓기만 함
- 2.  첫 쪽 제목 · 파일명으로 어느 학과 PDF인지 자동 판별
- 3.  지금 DB 값과 비교해 바뀐 칸만 표시 (예: 2025학번 졸업학점 999 -&gt; 130)
- 4.  같은 PDF를 다시 올리면 '바뀌는 값 없음' 표시, 여러 학과를 한 번에 처리

<sub>(화면 캡처 1장)</sub>

## 3. 공식 PDF 올리기 — 적용 -&gt; 카톡 즉시 반영 · 되돌리기

- 1.  「적용」을 눌러야 DB가 바뀜 (미리보기 단계에서는 그대로)
- 2.  적용 즉시 카톡 답변에 반영, 재색인 불필요
- 3.  바꾸기 전 값을 보관해 '되돌리기'로 원래 값 복구
- 4.  학과별 기준 문서(MD)와 전체 엑셀을 관리자 화면에서 내려받기 가능

<sub>(화면 캡처 2장)</sub>

## 3. 공식 PDF 올리기 — 표 추출 규칙 -&gt; 원본 42개 검증

- 1.  PDF에는 표 정보가 없고 글자 · 선의 좌표만 있음
- 2.  가로선 · 세로선으로 칸을 다시 그리고 글자를 들어갈 칸에 배정 (병합 셀 포함)
- 3.  학과 판별은 학과명 · 홈페이지 표기 · 별칭 중 가장 긴 일치로 결정
- 4.  AI가 아닌 고정 규칙이라 같은 PDF는 항상 같은 결과, 최종 반영은 관리자가 결정
- 5.  원본 PDF 42개를 기존 검수 데이터 523행과 대조해 차이 0건

<sub>(화면 캡처 3장)</sub>

## 4. 실제 임베딩 — 가짜 임베딩 -&gt; 로컬 qwen3 모델

- 1.  임베딩: 문장을 숫자 1,024개(벡터)로 바꿔 뜻이 비슷한 문장끼리 가깝게 놓는 방식
- 2.  지금까지는 글자 조각을 세는 가짜(mock) 임베딩이라 '별 보는' -&gt; '천체관측' 연결 불가
- 3.  이 Mac의 Ollama에서 qwen3-embedding(0.6B) 실행, 외부 API · 비용 없음
- 4.  동아리 61곳을 3조각(소개 · 활동 · 전체)씩 미리 벡터로 저장, 질문만 그때그때 변환
- 5.  모델이 바뀌면 서버 시작 때 자동으로 다시 임베딩

<sub>(화면 캡처 2장)</sub>

## 4. 실제 임베딩 — 임베딩 단독 정답 27 -&gt; 42

- 1.  학생이 실제로 묻는 형태의 질문 50개로 평가 (기본 30 + 키워드 사전을 만든 뒤 새로 쓴 20)
- 2.  키워드 사전을 끄고 임베딩만 쓰면 가짜 27개 -&gt; qwen3 42개 정답
- 3.  키워드 사전과 함께 쓰는 실제 운영 방식은 둘 다 50개 모두 정답
- 4.  남은 오답 8개 중 5개는 '동아리'라는 말이 없어 질문 분류에서 빠진 경우 (운영에서는 사전이 처리)

<sub>(화면 캡처 1장)</sub>

## 4. 실제 임베딩 — 한계 -&gt; '비슷한 동아리'로 안내

- 1.  작은 모델이라 '그런 동아리는 없다'를 가려내지 못함 (체스 -&gt; 보드게임, 스키 -&gt; 산악부)
- 2.  사전에 걸린 질문은 확정 답변, 임베딩으로만 찾은 결과는 '비슷한 동아리'로 안내 (왼쪽: 지난주, 오른쪽: 지금)
- 3.  관계없는 질문(점수 0.5 미만)에는 동아리를 붙이지 않음
- 4.  Ollama가 꺼지거나 3초 안에 답이 없으면 키워드 사전만으로 답변
- 5.  모델이 메모리에서 내려가면 첫 질문이 늦어져, 계속 올려 두고 서버 시작 때 미리 불러옴

<sub>(화면 캡처 2장)</sub>

## 5. 동아리 답변 — 점수 · 주소 노출 -&gt; 자연스러운 문장

- 1.  전에는 검색 점수 · 저장 시각(updated_at) · 링크 주소가 답변에 그대로 나옴 (왼쪽)
- 2.  이제 이름 · 분과, 한두 줄 소개, 정기 활동만 짧게 표시
- 3.  출처는 주소 대신 '에브리타임 모집 글 · 인스타그램 @…'처럼 이름으로 한 줄
- 4.  물어본 정보가 비어 있으면 '아직 확인되지 않았어요'로 답변 (지어내지 않음)
- 5.  끝에 '동아리 이름을 보내면 자세히' 안내

<sub>(화면 캡처 2장)</sub>

## 5. 동아리 답변 — 분야 질문 -&gt; 해당 동아리 모두

- 1.  '축구 동아리 뭐 있어'에 3곳만 나오던 것을 축구 동아리 6곳 모두로 변경
- 2.  '체스 동아리 있어?'가 목록 요청으로 잘못 분류돼 12곳을 나열하던 문제 수정
- 3.  범위 밖 질문 안내에서 'MVP' 같은 개발 용어 제거
- 4.  답변이 길면 동아리 소개 사이에서 말풍선을 나눔 (카카오 글자 수 제한)

<sub>(화면 캡처 1장)</sub>

## 6. 동아리 2차 수집 — 빈칸 -&gt; 모집 글로 보완

- 1.  에브리타임 동아리 · 학회 게시판에서 동아리별 최신 모집 글을 다시 읽음 (쪽당 3초 이상, 내부 API 미사용)
- 2.  회장 휴대폰 대신 동아리 공식 인스타그램 · 신청 방법으로 연락처 기록 (휴대폰 번호 0건)
- 3.  모집 글에도 시간이 없는 25곳은 비워 두고 '확인되지 않음'으로 안내
- 4.  수집 내용은 기록 파일로 남기고 명령 한 번으로 반영, 관리자가 웹에서 고친 칸은 덮지 않음

## 6. 동아리 2차 수집 — 활동 미확인 21곳 재확인
